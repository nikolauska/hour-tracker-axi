# AGENTS.md

## Working on hours-axi

This is a Node.js 24+ TypeScript CLI that records coding-agent working time from Claude Code hooks and reports hours per day and project. It prints TOON through `axi-sdk-js`. Use npm and the committed `package-lock.json`. Prefer Node standard-library APIs; add a runtime dependency only when it is clearly needed, and update the lockfile with the manifest.

- `src/cli.ts` registers commands through `runAxiCli`; each command lives in `src/commands/`. Return structured values and throw SDK errors (`src/errors.ts`) instead of formatting output by hand.
- `src/bin/hours-axi.ts` routes `hook` to `src/hook.ts` before loading the CLI, because hooks run on every agent tool call. Keep that path fast, silent (no stdout or stderr), and always exiting 0.
- The event log (`src/events.ts`) is append-only. Blocks, overlap splitting, and rounding are recomputed on every read (`src/blocks.ts`, `src/report.ts`), so fix a rule there instead of migrating stored data. Corrections are new events, never rewrites.
- Use ESM with `.js` relative import extensions. `dist/` is generated by `npm run build`; never edit or commit it or `node_modules/`.
- Add a comment where the reason for the code isn't obvious; comments explain why, not what.

## Docs

- Agent-facing usage lives in the CLI help (`src/commands/help.ts` and each command's `*_HELP`). `skills/hours-axi/SKILL.md` only points to it, so update the help, not the skill, when command behavior changes.
- Product rules (how hours are counted, what is recorded) live in `docs/domain.md` and `docs/domain/`. Read the relevant topic before changing counting, rounding, notes, corrections, or what the hook stores, and update it in the same change.
- Keep `README.md` minimal: install, a short quick start, and links.

## Local verification

Run from the repository root. Tests use temporary directories via the `HOURS_AXI_DATA_DIR`, `HOURS_AXI_CONFIG_DIR`, `CLAUDE_CONFIG_DIR`, and `HOME` overrides (`test/support/cli.js`), so they never touch real user data or Claude Code settings. Run relevant checks, fix failures caused by your change, and rerun them without asking.

- `npm ci` installs locked dependencies.
- `npm test` builds, then runs `test/` with Node's test runner under `TZ=UTC`.
- `npm run lint` runs oxlint and a TypeScript type check; `npm run fmt` formats and `npm run fmt:check` checks formatting.
- Before committing, run `npm run fmt:check`, `npm run lint`, and `npm test`.

## Boundaries

- Never run `hours-axi setup claude` (with or without `--remove`) or write to the real `~/.claude/settings.json` or `~/.local/share/hours-axi/` during development unless the user asks. Exercise them through the test overrides above.
- The hook stores timing metadata only. Do not add prompts, tool input or output, file contents, or transcripts to the event log.
- Use generic project names (`alpha`, `beta`) and ticket ids (`TICKET-1`) in tests and examples, never real project names.
- Keep commits small, one change each, with a conventional subject and a short description of what changed and why. Do not bypass hooks with `--no-verify`. Do not run `npm publish`.
